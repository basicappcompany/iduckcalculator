# iDuckCalculator

Free calculators that run in the browser. https://iduckcalculator.com. Part of the iDuck family by Basic App Company (iduckpdf.com, iduckimg.com, iduckconvert.com). Repo `basicappcompany/iduckcalculator` (PUBLIC; the owner decided to keep it public). It was recreated on 2026-11-23 with a cleaned history (see Gotchas): pull request numbers restart at #1, and the old repository is `basicappcompany/iduckcalculator-old` (private; the owner deletes it once the site is served from the new one).

## Stack and commands
Astro 7.4.13 (static output), Preact 11.2.0 islands, Tailwind 4.3.5, TypeScript 6.0.3 (7 is not supported by `astro check`; Dependabot ignores it), Vitest 5.1.1, Playwright 1.65.1, pnpm 12.14.0, Node 22.23.4 (`.node-version`). All versions are exact pins in `package.json`.

- `pnpm dev` | `pnpm build` (output `dist/`) | `pnpm preview`
- `pnpm verify` = `astro check` + `eslint` + `vitest run`. Run it before every commit.
- `pnpm test:e2e` = Playwright against a built site. Needs `pnpm build` first.
- CI (`.github/workflows/ci.yml`): check, lint, test, build and SEO audit on every PR and on `main`; the browser tests (e2e, about 70% of a run) on PRs only. Docs-only changes (`**.md`, `docs/**`) and changes to `.github/dependabot.yml` start no run, and a newer push cancels the older run. Dependabot opens npm and Actions updates monthly, minor and patch together in one PR (at most 2 npm PRs open); TypeScript major versions are ignored because `astro check` does not support TypeScript 7 yet (remove the ignore when it does). This saves Actions minutes: the free allowance is a pool shared by every repo on the account (checked on 2026-11-14), and a docs-only PR shows no checks, which is expected. On 2026-11-22 GitHub stopped starting jobs (annotation: "recent account payments have failed or your spending limit needs to be increased"): check github.com/settings/billing as the owner before assuming CI is broken; a run that fails in a few seconds with no steps is this, not a code problem. When CI is unavailable, run `pnpm verify`, `I18N_LOG=1 pnpm build`, `pnpm seo:check`, `pnpm i18n:audit` and `E2E_NO_BUILD=1 pnpm test:e2e` locally (the browser suite took about 25 minutes there on 2026-11-22).

## Layout
- `src/lib/calc/types.ts`: the `CalcDef` model. A calculator is a field list plus one pure `compute` function. Country-specific calculators set `country` (a `CountryCode`); a country other than India also pins its currency with `currency` (see `countries.ts`) and starts its slug with the code (`us-income-tax-calculator`). India's came first and keep plain slugs. Plan and status: `docs/country-tax-design.md`.
- `src/lib/calc/defs/*.ts`: the calculators by group; `src/lib/calc/index.ts` is the registry (home page, sidebar, search, sitemap and related links all read it).
- `src/lib/calc/expr.ts`: the safe expression parser behind the scientific calculator (no `eval`).
- `src/components/CalculatorTool.tsx` renders any calculator; `src/pages/[slug].astro` builds every calculator page.
- `src/pages/` the rest of the site; `src/lib/i18n/` the 11 languages (`en.ts` is the source text, one file per language, `index.ts` has the helpers and `PAGE_LANGS`); `src/lib/seo.ts` has `LAST_UPDATED` (footer date).
- `tests/unit` (Vitest), `tests/e2e` (Playwright), `docs/status.html` (self-contained project status page, no external requests), `PROGRESS.md` (checklist).

## Guides
- `src/lib/guides.ts` holds the first three guides and combines the rest from `guides-loans.ts`, `guides-savings.ts`, `guides-maths.ts`, `guides-dates.ts`, `guides-health.ts` and `guides-students.ts`. The guides page groups a guide under its first linked calculator's group.
- A guide needs: title (60 characters or fewer), description (70 to 160), an answer-first intro (25 to 60 words), steps, sections, 4 or more FAQs, 300 or more words, links to calculators and to related guides.
- Every number a guide quotes must be recomputed in `tests/unit/guides.test.ts` from the calculators. Add a claim there when you add a guide, and write the figure the way the test formats it (Indian grouping, a real minus sign).
- Every live calculator must be linked from at least one guide; the test enforces it. Health guides keep the not-medical-advice line.

## Page content that search and AI answers quote
- `src/lib/calc/answers.ts`: the 40 to 60 word answer under each heading is composed from a "what it is" sentence, `formula[0]` and the example sentence in `quick`. Adding a calculator means adding its entry there (a test fails otherwise).
- `src/lib/calc/reference.ts`: one reference table per calculator, every cell computed by the calculator. Add one for each new calculator.
- `src/lib/calc/sources.ts`: finance and health calculators need a `TRUST` entry (basis and reference links) and `LAST_REVIEWED` is the date shown as "Last reviewed". Re-check the formulas and links, then bump the date.
- `pnpm seo:check` (CI) enforces titles under 60 and descriptions under 155 characters, unique titles, one h1, robots meta, canonical, sitemap with lastmod, JSON-LD fields and the AI-crawler groups in robots.txt.
- Security headers: `public/_headers` plus `scripts/csp.mjs` (hashes of inline scripts into the CSP). No inline `style=` attributes or event handlers: use classes. Browser tests run under the production CSP.

## Adding a calculator
1. Add an entry to the right file in `src/lib/calc/defs/`: slug, name, group, summary, quick answer, title (<= 65 chars), description (70 to 175), fields, `compute`, formula, worked example, `how`, 4 to 6 FAQs, exactly 3 `related` slugs that exist.
2. Add a known-answer unit test (the worked example's numbers). The registry test already enforces the page fields.
3. Run `pnpm verify`, `pnpm build`, `pnpm test:e2e`. The e2e suite reads the registry, so the new page is covered automatically.
4. Tax and savings-scheme calculators: read the official source first (incometax.gov.in, India Post, the Finance Ministry, or the country's own authority: IRS, HMRC, CRA, ATO, Bundeszentralamt/BMF), put the tax year and the date it was read in `rules`, and never use a rate from memory. A tax calculator must set `country` (a test enforces it).

## Gotchas
- A built calculator counts as done only with its page on `main`, a known-answer test, FAQs and 3 related links.
- Do not trust this machine's DNS for iduckcalculator.com: an office or VPN resolver cached the old GoDaddy parking page, which answers 200 for every path. Check the live site with `curl --resolve iduckcalculator.com:443:104.21.85.203 https://iduckcalculator.com/...` (use `MSYS_NO_PATHCONV=1` in Git Bash) or from a phone on mobile data.
- The repo is public, so nothing secret may ever be committed. On 2026-11-14 a local launcher (`claude-toggle.bat`) holding an API key was committed by a blanket `git add -A` and sat in public history until 2026-11-23. It is now in `.gitignore`, and the history was rewritten without it (and without the company mailbox, replaced by GitHub noreply identities) and published as a new repository with the same name on 2026-11-23. Every commit hash and pull request number quoted in older notes (#14 to #49) belongs to the old repo `iduckcalculator-old` and does not exist here. The old repo is private but still holds the key, so that key had to be rotated and the old repo is to be deleted. Rules: stage files by name (or check `git status` first) instead of `git add -A`; never print a credential into a reply; GitHub secret scanning and push protection are free on a public repo and should be on (owner setting, see AUDIT.md A5b). Commits use the GitHub noreply identity (repo-local `git config user.email 32772183+basicappcompany@users.noreply.github.com`, name `basicappcompany`), never the company mailbox, and no file may name the mailbox (write "the company inbox").
- `pnpm test:e2e` rebuilds the site inside Playwright's 180 s web-server limit; on this machine the build alone takes 70 to 110 s and the run has timed out (and left a half-empty `dist/`, so the preview answers 404). Run `pnpm build` first, then `E2E_NO_BUILD=1 pnpm test:e2e`: it serves the existing `dist/` on 127.0.0.1 (no temporary config needed; `localhost` may resolve to IPv6 and miss the server). CI does the same, so the site is built once per run, not twice. 152 passed this way in 2.8 to 4.6 minutes.
- The e2e test "typing into the EMI calculator updates the result live" failed once when the machine was heavily loaded and passed alone and on repeat. If it fails, re-run it before suspecting the code.
- Every page defaults to light, whatever the device setting: `AppShell.astro` renders `data-theme="light"` on all of them. A saved choice (`duck.theme` in localStorage: light, dark or system) wins on every page until changed; "system" (Match my device) removes the attribute so the device setting applies. All logic is in `src/lib/theme-client.ts`, unit-tested in `tests/unit/theme.test.ts`.
- The helper (`src/lib/helper.ts`, `src/components/ChatHelper.tsx`) is a plain matcher, not an AI: it handles greetings, simple sums via `expr.ts`, "X% of Y", topic answers and calculator matches. Keep it free of network calls.
- Search Console and Bing have the sitemap; the Google verification TXT record in Cloudflare DNS must stay. Account security settings are listed in AUDIT.md; do not change them without the owner.
- Localization (the whole site, 11 languages): English (US) is at the root; en-GB, hi, bn, pt-br, id, ru, de, es, fr and tr are under `/de/`, `/pt-br/` and so on (the set iduckpdf.com and iduckimg.com use). Pages are built per language at build time with the right `lang`, hreflang links, `og:locale` and sitemap alternates. Calculators, guides, the guides list, the calculators list, the home page and About, Roadmap, Support and How we check exist in every language. Privacy, Terms, the helper chat, Feedback, Request and Settings stay English (no translated copy, so the language menu sends you to that language's home page).
- How it works: the English text stays in the code. A page asks `tt('English text')` (`trFor(lang)` in `src/lib/i18n/loader.ts`) for each string; the answer comes from `src/i18n/catalog/<lang>.json`, a flat file of English string -> translation (`src/lib/i18n/catalog.ts`). A string with numbers can be one entry with `{0}`, `{1}` for the numbers, so "At 7.1% a year" and "At 8.2% a year" share "At {0}% a year"; a note of several sentences is translated sentence by sentence; links inside a sentence are named placeholders (`{privacy}`). The calculator island gets just the strings its calculator needs (`islandStrings`). English (UK) is made from the US text by `ukify` (`uk.ts`), so write English source in US spelling. The menus, footer and home page text are in `src/lib/i18n/<code>.ts` (chrome and home).
- Keeping it complete: `pnpm test` fails (tests/unit/i18n-catalog.test.ts) if any language lacks a translation for any string the site can show, or changes a number, placeholder or a title/description length. `I18N_LOG=1 pnpm build` followed by `pnpm i18n:audit` (both run in CI) fails if a translated page showed English text. So: change English text, add a calculator or a guide, or add `tt('...')` somewhere, and the tests list what is missing.
- Reworded English no longer means translating again: after exporting `source.json`, run `node scripts/i18n/orphans.mjs` (lists catalog entries no string uses and strings with no entry, and pairs a reworded string with the old one when the numbers match and 60% of the words are shared); `--apply` moves those translations to the new wording in all nine catalogs and lists them in `src/i18n/recheck.json` for a native speaker. `pnpm test` still checks numbers, placeholders and title/description lengths, so a moved entry that is now too long fails and is re-translated. Use `scripts/i18n/merge-round.mjs <round>` (validates, merges only that round, all nine languages) instead of `merge.mjs`. `docs/i18n/STYLE.md` and `LANGS.md` are the translator instructions (copy them to `i18n-work/` before a round).
- `scripts/i18n/merge.mjs` re-applies every file in `i18n-work/<lang>/out/` in name order, so it overwrites entries that were later fixed in the catalog. After the first merge of a language, merge only the new round (a small script that reads just `out/<round>.json` and the matching chunk). `i18n-work/misses.log` is appended to by every `I18N_LOG=1` build: empty it (`: > i18n-work/misses.log`) before the build you audit. The collector reads guide files named `guides*.ts` (any number of hyphen parts, such as `guides-us-tax.ts`).
- Adding or changing English strings: run `I18N_EXPORT=1 pnpm exec vitest run tests/unit/i18n-collect.test.ts` (writes i18n-work/source.json), then `node scripts/i18n/chunk.mjs <lang> 30000 r9-` for each language (only the missing strings), have each chunk translated into `i18n-work/<lang>/out/r9-001.json` following `i18n-work/STYLE.md` and the glossary in `i18n-work/LANGS.md`, check with `node scripts/i18n/validate.mjs <lang> r9-001`, and merge with `node scripts/i18n/merge.mjs <lang>`. The validator keeps every number, the rupee sign, placeholders and the title and description limits. `i18n-work/` is not committed; the catalogs are.
- Where strings come from (so the collector finds them): `scan.ts` takes the sentence-like literals of the calculator and guide data files, the `tt('...')` and `tr('...')` calls in pages, components and `src/pages/*.ts`, `src/lib/i18n/palette.ts` and `src/lib/i18n/page-data.ts`, and a sweep runs every calculator with the default and with odd numbers to collect its labels, notes and errors. Put the text of any new list on a page in `page-data.ts` (or wrap it in `tt('...')` where it is shown), not in a bare array in a component.
- The translations of nine languages were written by Claude Haiku (sub-agents, in chunks, each checked by the validator); Sonnet 5.5 wrote the menus and home page texts. None has been read by a native speaker, so every page of those languages says so at the top. Never set `reviewed: true` for a language in `src/lib/i18n/languages.ts` before a native speaker has read it. Number words stay as digits (the validator insists), dates use Western digits, and the Indian terms (lakh, crore, EMI, SIP, PPF) stay as they are.
- Date maths: `ymd()` in `src/lib/calc/defs/dates.ts` counts years, months and days. A start day later than the previous month is long (31 Jan to 1 Mar) falls back to clamped month arithmetic, and a 29 Feb birthday counts as 1 March in other years. Do not swap it for a different convention without changing the age and date-difference tests.
- US federal tax (income tax and take-home pay) is in `src/lib/calc/defs/us-tax.ts`, tax year 2026, read from IRS pages on 2026-11-15: Revenue Procedure 2025-32 section 4 (tables, standard deductions), IRS Topic 751 (Social Security wage base, Medicare) and Topic 560 (Additional Medicare Tax). `tests/unit/us-tax.test.ts` checks every band against the amounts the IRS prints. IRS pages load with a plain fetch but the Chrome tool hung on irs.gov; the revenue procedure is a PDF (`pdftotext -layout` works); the SSA wage-base page returns 403 to scripts. Each October or November the IRS publishes the next year's inflation adjustments: re-read, change the numbers, bump `US_RULES_READ_ON`, and update the tests and both US guides. The `/tax/` and `/tax/<code>/` hubs (`TaxHubPage.astro`) list every country that has a calculator.
- UK Income Tax and take-home pay are in `src/lib/calc/defs/uk-tax.ts`, tax year 2026 to 2027, read from GOV.UK on 2026-11-15 (income-tax-rates, scottish-income-tax, the employer rates and thresholds page). GOV.UK prints the bands as income with the standard £12,570 allowance; the code stores taxable-income limits (printed limit minus £12,570, and £125,140 stays as is), and `tests/unit/uk-tax.test.ts` checks that. Scotland is a `region` field. The tax year starts 6 April: re-read the pages each April and after every Budget, change the numbers, bump `UK_RULES_READ_ON` and update the tests and both UK guides. The student loan page carries no tax year, so student loans are not in the calculator.
- Canada (federal only) is in `src/lib/calc/defs/ca-tax.ts`, tax year 2026, read from CRA pages on 2026-11-15: the current-year rates page, the indexation page (basic personal amount, Canada employment amount), the CPP, CPP2 and EI pages and the T4127 payroll formulas (credit rate 14% = the lowest federal rate; the extra CPP is deducted from income and only base CPP and EI earn a credit). Provincial and territorial tax is not included and every Canada page says so; Quebec (QPP, lower EI) is not modelled. The indexation page URL must be the `adjustment-personal-income-tax-benefit-amounts.html` one (a guessed URL 404s); the T4127 January page is long and the fetch tool returns part of it as a summary, so check formulas against the verbatim part. Each fall the CRA publishes the next year's CPP, EI and indexed amounts: re-read, change the numbers, bump `CA_RULES_READ_ON`, update `tests/unit/ca-tax.test.ts` and both Canada guides. Descriptions are capped at 154 characters in every language: when the English is shortened, delete its old key from the nine catalogs before re-translating.
- Australia (resident, income tax and Medicare levy) is in `src/lib/calc/defs/au-tax.ts`, income year 2026-27, read on 2026-11-22 from the ATO pages Tax rates - Australian resident, Low income tax offset and Medicare levy reduction for low-income earners (pasted by the owner: ato.gov.au returns 403 to scripts and the Chrome tool hung on it, and spoofing a browser is not allowed). Resident rates 0 / 15 / 30 / 37 / 45% with the $18,200 tax-free threshold, the low income tax offset ($700 to $37,500, then $700 less 5c per $1, then $325 less 1.5c per $1 from $45,000, nil at $66,667), and the 2% Medicare levy reduced by 10c per $1 over the lower threshold (the ATO example, $29,000 gives $98.90, is a test). The rates page lost its year headings in the paste; the 15c table was read as 2026-27 from its order and the page range. The Medicare levy thresholds ($28,011 and $35,013) are the 2025-26 ones, the latest the ATO had published: re-read the Medicare levy pages when the 2026-27 thresholds appear. Left out and said on every page: other offsets, the Medicare levy surcharge, HELP, family and senior (SAPTO) thresholds, salary sacrifice; employer super is paid on top and not taken off. The tax year starts 1 July: re-read in July and after each May Budget, change the numbers, bump `AU_RULES_READ_ON`, update `tests/unit/au-tax.test.ts` and both Australia guides. `scripts/rules-watch.mjs` cannot check the ATO (403 to scripts), so Australia is not covered by the weekly check.
- Germany income tax is in `src/lib/calc/defs/de-tax.ts`, tax year 2026, read on 2026-11-23 from the consolidated laws on gesetze-im-internet.de (they load with a plain fetch, no bot block): EStG section 32a (the tariff text says "ab dem Veranlagungszeitraum 2026": basic allowance 12,348, zones to 17,799 / 69,878 / 277,825, formulas typed exactly as printed, tax and income rounded down to whole euros, splitting tariff = twice the tax on half the income), and SolzG sections 3 and 4 (5.5%, limit 20,350 single / 40,700 joint, never more than 11.9% of the excess, cents cut off). `tests/unit/de-tax.test.ts` checks the zone joins and hand-worked values. The calculator taxes a taxable income you enter; church tax, child allowances, the progression clause and special rules are left out and stated on the page. Also read, for the take-home pay calculator that comes next: the 2026 social insurance figures (contribution ceilings 101,400 pension and unemployment, 69,750 health and care: bundesregierung.de "Beitragsbemessungsgrenzen 2026"; pension 18.6% from RVBeitrSBek 2026; unemployment 2.6% SGB III section 341; health 14.6% SGB V section 241 plus the 2.9% average additional contribution from the BMG page, employer and employee halves; care 3.6% plus 0.6% for the childless paid by the employee alone, Saxony differs: BMG page "Finanzierung der sozialen Pflegeversicherung"), EStG sections 9a (1,230) and 10c (36), and section 10 (pension contributions deductible in full from 2023; health contributions less 4%; care in full; the 1,900 / 2,800 limit). A payslip's Lohnsteuer follows the BMF Programmablaufplan (PAP), not the annual tariff, so take-home pay must implement the PAP 2026 (decision of the owner on 2026-11-23); do not build it with the assessment method. Each autumn the new tariff is published: re-read section 32a, change the numbers, bump `DE_RULES_READ_ON`, update the tests and the guide. The euro uses English grouping (`en-IE` in `format.ts`) so amounts match the English prose on every language's pages.
- `scripts/rules-watch.mjs` (weekly workflow `rules-watch.yml`, opens an issue) checks that the official pages still print the figures the US, UK and Canada calculators use. When you change a rate, update its line there too. Unreachable pages are skipped, not failed; India and Australia/Germany are not covered yet.
